# Copyable examples

Complete code for the [Flatzz README](../README.md). The examples use Zig 0.17.0
and the actual `Rocket` module generated from the schema below.

## Run and test

From the Flatzz checkout:

```sh
zig build run-readme
zig build check test
```

`run-readme` generates the schema on the host, then builds and runs
[main.zig](../example/readme/main.zig). The default `check` and `test` steps
compile and run the three tests copied below against freshly generated code.
They are unavailable with `-Dschema-tools=false`.

Expected program output:

```text
allocated: id=7, fuel=80, pilot=Ziguana, payload[0]=1
received: id=7, fuel=80, pilot=Ziguana, payload[0]=1
edited: id=7, fuel=79, pilot=Pilot01, payload[0]=1
```

## Shared imports

Each test below is independent. Put these imports before any copied test.
The `rocket` module imports `flatzz`; the application does not import a compiler.

```zig
const std = @import("std");
const flatzz = @import("flatzz");
const generated = @import("rocket");

const Rocket = generated.Rocket;
```

To test a copied file, first generate its schema from the Flatzz root:

```sh
zig build compiler
zig-out/bin/flatzz --zig example/readme/rocket.fbs > /tmp/flatzz-rocket.zig
```

Save the imports and one or more complete tests as `/tmp/flatzz-example.zig`,
then run from the Flatzz root:

```sh
zig test --dep flatzz --dep rocket -Mroot=/tmp/flatzz-example.zig -Mflatzz=src/runtime.zig --dep flatzz -Mrocket=/tmp/flatzz-rocket.zig
```

## 1. Serialize and read back

[README](../README.md#1-serialize-and-read-back) ·
[Runnable source and tests](../example/readme/main.zig)

`serializeAlloc` returns an owner. `std.testing.allocator` detects leaked storage
when this test runs; `deinit` releases it after all borrowed views are finished.

```zig
test "1. serialize and read back" {
    const allocator = std.testing.allocator;
    const rocket: Rocket = .{
        .id = 7,
        .fuel = 80,
        .pilot = "Ziguana",
        .payload = &.{ 1, 2, 3 },
    };
    const result = try rocket.serializeAlloc(allocator, .{});
    defer result.deinit(allocator);

    try Rocket.verify(result.bytes, .{});
    const view = try Rocket.read(result.bytes);
    try std.testing.expectEqual(@as(u32, 7), view.id);
    try std.testing.expectEqual(@as(f32, 80), view.fuel);
    try std.testing.expectEqualStrings("Ziguana", view.pilot.?);
    try std.testing.expectEqual(@as(u8, 1), try view.payload.?.get(0));
}
```

## 2. Use caller-owned storage

[View illustration](../README.md#2-use-caller-owned-storage) ·
[Runnable source and tests](../example/readme/main.zig)

No allocator is passed to this path. The returned frame borrows a suffix of the
usable storage; it is not the entire 256-byte capacity. The pointer checks show
that the string is borrowed from the frame. Scalars are decoded by value, and
vector elements are read lazily with `get`.

```zig
test "2. use caller-owned storage" {
    const rocket: Rocket = .{
        .id = 7,
        .fuel = 80,
        .pilot = "Ziguana",
        .payload = &.{ 1, 2, 3 },
    };
    var storage: [256]u8 align(flatzz.storage_alignment) = undefined;
    const bytes = try rocket.serialize(&storage, .{});

    try Rocket.verify(bytes, .{});
    const view = try Rocket.read(bytes);
    try std.testing.expectEqualStrings("Ziguana", view.pilot.?);
    try std.testing.expectEqual(@as(f32, 80), view.fuel);
    try std.testing.expectEqual(@as(u8, 3), try view.payload.?.get(2));

    const pilot_start = @intFromPtr(view.pilot.?.ptr);
    const frame_start = @intFromPtr(bytes.ptr);
    try std.testing.expect(pilot_start >= frame_start);
    try std.testing.expect(pilot_start + view.pilot.?.len <= frame_start + bytes.len);
}
```

## 3. From FBS to generated Zig

[View illustration](../README.md#3-from-fbs-to-generated-zig) ·
[Schema file](../example/readme/rocket.fbs)

The illustration abbreviates the generated declarations. This is the full schema:

```fbs
table Rocket {
  id:uint;
  fuel:float = 100;
  pilot:string;
  payload:[ubyte];
}
root_type Rocket;
```

The compiler produces the following complete module. Build-time generation is the
source of truth; the application uses its native fields and schema operations.

```zig
// Generated by flatzz --zig. Do not edit.
// Wire IDs and layouts come from reflection metadata, never the native ABI.
// Strings and views borrow their buffer; builders use caller-owned storage.
const runtime = @import("flatzz");
const types = @This();
pub const Rocket = struct {
    id: u32 = fields.id.default,
    fuel: f32 = fields.fuel.default,
    pilot: ?[]const u8 = null,
    payload: ?[]const u8 = null,
    pub const fields = .{
        .id = runtime.ScalarField(u32, 0, 0),
        .fuel = runtime.ScalarField(f32, 1, @bitCast(@as(u32, 1120403456))),
        .pilot = runtime.ReferenceField(2, .string, .{}),
        .payload = runtime.ReferenceField(3, .{
            .vector = runtime.ScalarCodec(u8),
        }, .{}),
    };
    pub const Schema = runtime.Schema(@This(), fields);
    pub const Field = Schema.Field;
    pub const View = Schema.View;
    pub const serialize = Schema.serialize;
    pub const serializeAlloc = Schema.serializeAlloc;
    pub const read = Schema.read;
    pub const update = Schema.update;
    pub const borrowMutable = Schema.borrowMutable;
    pub const verify = Schema.verify;
    pub const WriteOptions = runtime.WriteOptions;
};
```

The `fuel` descriptor preserves the FBS default `100` as its exact `f32` bit
pattern. `id` is an external schema field name. The generated wire metadata,
not native Zig struct layout, defines the FlatBuffer representation.

## 4. Read and edit existing bytes

[README](../README.md#4-read-and-edit-existing-bytes) ·
[Runnable source and tests](../example/readme/main.zig)

This example creates a frame to stand in for received bytes. Verify untrusted
input before using schema views; keep it unchanged during verification. `read`
alone performs local access checks and is not a substitute for `verify`.

The scalar in `before` remains `80` after mutation, while its borrowed pilot
string observes the new seven-byte name. An unequal-length replacement fails
without changing the field.

```zig
test "4. read and edit existing bytes" {
    const rocket: Rocket = .{
        .id = 7,
        .fuel = 80,
        .pilot = "Ziguana",
        .payload = &.{ 1, 2, 3 },
    };
    var storage: [256]u8 align(flatzz.storage_alignment) = undefined;
    const bytes = try rocket.serialize(&storage, .{});
    try Rocket.verify(bytes, .{});
    const before = try Rocket.read(bytes);

    try std.testing.expect(try Rocket.update(bytes, .fuel, 79));
    try std.testing.expect(try Rocket.update(bytes, .pilot, "Pilot01"));
    try Rocket.verify(bytes, .{});
    const after = try Rocket.read(bytes);

    try std.testing.expectEqual(@as(f32, 80), before.fuel);
    try std.testing.expectEqual(@as(f32, 79), after.fuel);
    try std.testing.expectEqualStrings("Pilot01", after.pilot.?);
    try std.testing.expectEqualStrings("Pilot01", before.pilot.?);
    try std.testing.expectError(error.LengthMismatch, Rocket.update(bytes, .pilot, "short"));
    try std.testing.expectEqualStrings("Pilot01", (try Rocket.read(bytes)).pilot.?);
}
```

For nested struct mutation, see `Reading.borrowMutable(bytes, .location)` in the
[generated Reading example](../example/generated/main.zig). `borrowMutable` is
for structured fields, not scalar or string replacement. Mutable vector views
preserve their element codec's access rules; scalar elements remain copied values.

## Complete runner

[Source](../example/readme/main.zig) · [Schema](../example/readme/rocket.fbs)

The build imports `flatzz` and the generated `rocket` module. This complete
program allocates a frame, prints its fields, then uses fixed storage for a
receive/read/edit/print flow. The receive step uses locally serialized bytes;
there is no networking or mapping hidden in the example.

```zig
//! Generate Rocket from rocket.fbs, serialize it, and edit existing bytes.
//! Run with `zig build run-readme`; `zig build test` checks the copyable examples.

const std = @import("std");
const flatzz = @import("flatzz");
const generated = @import("rocket");

const Rocket = generated.Rocket;

/// Print a borrowed view while its backing storage is still alive.
fn printRocket(output: *std.Io.Writer, label: []const u8, view: Rocket.View) !void {
    const pilot = view.pilot orelse return error.MissingPilot;
    const payload = view.payload orelse return error.MissingPayload;
    try output.print("{s}: id={d}, fuel={d}, pilot={s}, payload[0]={d}\n", .{
        label, view.id, view.fuel, pilot, try payload.get(0),
    });
}

/// Create an owned frame, then receive and edit a separate caller-owned frame.
pub fn main(init: std.process.Init) !void {
    const rocket: Rocket = .{
        .id = 7,
        .fuel = 80,
        .pilot = "Ziguana",
        .payload = &.{ 1, 2, 3 },
    };
    var output_buffer: [512]u8 = undefined;
    var output = std.Io.File.Writer.init(.stdout(), init.io, &output_buffer);

    const result = try rocket.serializeAlloc(init.gpa, .{});
    defer result.deinit(init.gpa);
    try Rocket.verify(result.bytes, .{});
    try printRocket(&output.interface, "allocated", try Rocket.read(result.bytes));

    var storage: [256]u8 align(flatzz.storage_alignment) = undefined;
    const bytes = try rocket.serialize(&storage, .{});
    try Rocket.verify(bytes, .{});
    try printRocket(&output.interface, "received", try Rocket.read(bytes));
    if (!try Rocket.update(bytes, .fuel, 79)) return error.MissingFuel;
    if (!try Rocket.update(bytes, .pilot, "Pilot01")) return error.MissingPilot;
    try Rocket.verify(bytes, .{});
    try printRocket(&output.interface, "edited", try Rocket.read(bytes));
    try output.interface.flush();
}
```

The generated module needs no allocator to read or edit existing bytes. The
application is responsible for input framing, mapping, synchronization, and
keeping borrowed storage valid.

## Ownership and implementation notes

Descriptor factories remain in `schema.zig`, preserving their type names and lazy
recursive references. `native_graph` owns preflight and packing, recursing through
the existing descriptor and table-construction contract without adding public schema
methods. It shares presence and work-accounting policy with `schema.zig` through
lazy imports. Field access accepts already checked tables; its callers select framing
and read-only or mutable access.
Storage sizing, native alias preflight, packing, and wire verification retain their
separate validation contracts.

FBS parsing uses the caller's arena for copied sources, unresolved declarations,
metadata, and diagnostics. Keep that arena alive until all consumers finish.
Includes follow `Compilation.load -> Parser -> Compilation.load` directly.
Public types stay in the parser facade; internal modules use the same identities.
BFBS encoding owns its growing buffer and completed handles; decoding copies
metadata into the caller's arena and retains its own traversal limits and object
identity cache. The documented BFBS facade retains the public errors and options.
Code generation borrows its input schema and owns one temporary scratch arena
through AST finalization. `Generator` and `Syntax` borrow that allocator; `Syntax`
copies temporary child lists into the arena. The returned formatted source is separately owned by
the caller and freed with its allocator.

Builders use caller-owned buffers. `serializeAlloc` returns a `Serialized` owner
that must be released once with the same allocator. Borrowed views expire when
their backing storage is reused or released; structural edits invalidate checked
table metadata. Use explicit Builder handles when table sharing is required.

Further Scanner, name-handling, Builder, and storage splits remain deferred.
The current boundaries follow ownership and validation responsibilities rather
than a maximum file size.
